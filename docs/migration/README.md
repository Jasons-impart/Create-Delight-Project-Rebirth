# 从 Forge 1.20.1 移植内容

旧包材料、模组 ID 与配方 API 在 NeoForge 1.21.1 上可能已经改变。先查[逐模组清单](mods.md)确认前置和替代方案，再查[当前状态](status.md)确认玩法范围，选择一项能独立验收的内容。

| 本地变量 | 用途 |
| --- | --- |
| `CDPR_0488_SOURCE` | 用于逐项移植及验收后清理的 0488 工作副本 |
| `CDPR_LEGACY_REPO` | 只读参考仓库，用来确认更新版 Forge 整合包的替代材料和实现 |
| `CDPR_CORE_REPO` | 查询目标注册、Java API 和已实现的兼容逻辑 |
| `CDPR_BACKUP_DIR` | 存放旧源归档、逐文件哈希、验证记录和清理清单 |

实际位置按[本机路径说明](../README.md#本机路径)配置。先确认正在读取哪个源、采用了哪个提交，再记录对应的模组版本。

1. 在 0488 找到原配置、脚本、资源和依赖。遇到缺失物品或模组，按[上游对照](upstream.md)查最新版旧包如何处理；核对目标描述符、注册表和配方类型后决定迁移、替代、挂起或重写。
2. 按工具函数、注册、标签、配方、客户端表现、可选联动分别迁移。目标配置用当前模组生成的结构。注册和 Java 机制核对 Core，脚本遵循 [KubeJS 规范](../development/kubejs.md)。
3. 在目标实例验证实际行为。记录用了哪个 Core 构建、服务端和客户端分别验证了什么。涉及旧存档或 GUI 时单独验收。
4. 确认迁移完成并备份后，只清理指定 0488 工作副本中的对应内容。先逐文件核验归档，混合文件只移除已完成的分支。放弃或重写的功能先记下维护决定。最新版旧包参考仓库始终只读。
5. 仍待实现、确认或验收的事项更新到[当前状态](status.md)；已发生的批次验证、哈希和备份标识写入[历史记录](../archive/README.md)。

旧版任务章节、奖励、任务文本和任务专用扩展已决定重新设计；混合脚本中的非任务玩法按其自身用途评估。
